# Навык Яндекс Алисы на Gemini — скопируйте и развивайте свой проект

Это исходный код вебхука для навыка Яндекс Алисы. Скопируйте репозиторий в свой GitHub, подключите свою копию к Vercel и настройте собственные API-ключи. После этого можно менять поведение навыка и развивать его как отдельный проект.

В проекте:

- **Gemini** формирует ответы.
- **Serper** по желанию добавляет поиск в интернете для актуальных вопросов.
- **Upstash Redis** по желанию хранит историю между сессиями и помогает учитывать прежние разговоры.
- **Vercel** принимает запросы от Яндекс Диалогов и запускает вебхук.

## Что потребуется

- GitHub — чтобы создать свою копию исходного проекта.
- Vercel — чтобы развернуть вебхук.
- Google AI Studio — чтобы получить ключ Gemini.
- Яндекс Диалоги — чтобы создать навык и настроить вебхук.
- Serper и Upstash — только если нужны поиск в интернете и долговременная память.

## 1. Создайте собственную копию

1. Войдите в GitHub и откройте [исходный репозиторий](https://github.com/ruslanpodzorovraw-collab/alice-gemini-serper-template).
2. Нажмите **Fork** и создайте копию в своём аккаунте. Можно выбрать другое имя репозитория.
3. Откройте созданную копию. Все дальнейшие настройки и изменения выполняйте в ней, а не в первоисточнике.

Fork создаёт отдельный репозиторий, который вы можете менять независимо. Когда в первоисточнике появятся полезные обновления, GitHub позволит отдельно перенести их в копию через **Sync fork**; сначала просмотрите предлагаемые изменения, чтобы не затереть свои доработки.

## 2. Разверните свою копию в Vercel

1. Откройте [Vercel](https://vercel.com/dashboard) и выберите **Add New… → Project**.
2. Импортируйте репозиторий, созданный через Fork. Если GitHub спросит доступ, разрешите Vercel видеть этот репозиторий.
3. Оставьте корневую папку проекта без изменений и нажмите **Deploy**. Если Vercel предложит настроить переменные до первого запуска, добавьте их по следующему разделу; иначе можно добавить после импорта.
4. Откройте настройки проекта **Settings → Environment Variables** и добавьте нужные переменные.
5. После добавления или изменения переменных выполните **Deployments → Redeploy**. Дождитесь статуса **Ready**.
6. Откройте **Settings → Domains** или страницу готового Production-развёртывания и скопируйте домен проекта. Адрес вебхука будет выглядеть так: `https://имя-проекта.vercel.app/api`.

При включённой интеграции GitHub новый коммит в ветку `main` вашей копии автоматически запускает Production-развёртывание. Ветки и pull request обычно получают отдельные Preview-развёртывания.

## 3. Добавьте API-ключи

Создавайте ключи в аккаунтах соответствующих сервисов и добавляйте их только в Vercel: **Project → Settings → Environment Variables**. Для Production выберите окружение **Production**. Если хотите тестировать Preview-развёртывания, добавьте переменные также для **Preview**.

| Переменная | Нужна? | Где получить / что делает |
| --- | --- | --- |
| `GEMINI_API_KEY` | Да | Создайте ключ в [Google AI Studio](https://aistudio.google.com/app/apikey). Без него навык не сможет сформировать ответ. |
| `SERPER_API_KEY` | Нет | Получите ключ на [serper.dev](https://serper.dev). Включает поиск в интернете для вопросов о свежих и актуальных данных. Без него обычные ответы Gemini работают. |
| `GEMINI_MODEL` | Нет | Имя доступной вашей учётной записи модели Gemini. По умолчанию используется `gemini-3.5-flash-lite`. Если модель недоступна, укажите другую доступную модель. |
| `UPSTASH_REDIS_REST_URL` | Нет | REST URL базы данных из раздела REST API в [Upstash](https://console.upstash.com/). |
| `UPSTASH_REDIS_REST_TOKEN` | Нет | REST Token той же базы Upstash. Добавьте обе переменные Upstash, чтобы включить долговременную память. |

После изменения переменных сделайте **Redeploy**: уже завершённое развёртывание не подхватит новые значения автоматически.

### Как работает долговременная память

Память включается только при наличии обеих переменных Upstash. Сохраняются тексты сообщений пользователя и ответов навыка — максимум 500 сообщений вместе, с автоматическим удалением по истечении 30 дней. Для ответа модель получает недавние сообщения и найденные по теме фрагменты истории. Пользователь может попросить: **«Забудь наши прошлые диалоги»** — навык удалит сохранённую историю.

Если переменные Upstash не заданы, навык продолжает работать с краткой историей, передаваемой Яндекс Диалогами. База данных не обязательна для запуска проекта.

## 4. Подключите вебхук в Яндекс Диалогах

1. Откройте [Яндекс Диалоги](https://dialogs.yandex.ru/developer/) и создайте свой навык с типом бэкенда **Вебхук**.
2. В настройках бэкенда вставьте адрес своего Vercel-проекта с путём `/api`, например `https://имя-проекта.vercel.app/api`.
3. Сохраните настройки и откройте встроенный раздел **Тестирование**.
4. Отправьте навыку обычный вопрос. Для проверки поиска спросите, например, актуальный курс или сегодняшнюю погоду.
5. Если доступно в настройках навыка, включите **Использовать хранилище данных в навыке**, чтобы Яндекс также передавал и сохранял пользовательское состояние между сессиями.

Чтобы проверить адрес вебхука отдельно, откройте его в браузере. Запрос `GET` к `https://имя-проекта.vercel.app/api` должен вернуть JSON с `"ok": true`.

До голосового запуска используйте встроенный тестер Яндекс Диалогов. Для проверки через колонку сделайте навык доступным для тестирования и войдите на колонке или в приложении Алисы в аккаунт, связанный с консолью разработчика. Скажите: **«Алиса, запусти навык [активационное имя]»**. См. также [инструкцию Яндекса по тестированию](https://yandex.ru/dev/dialogs/alice/doc/ru/test).

## 5. Развивайте свой проект

Изменяйте файлы в своей копии GitHub. Чтобы проверить код до публикации, установите [Node.js 22 или новее](https://nodejs.org/) и выполните в папке проекта:

```sh
npm test
```

У проекта нет дополнительных npm-зависимостей; тесты запускаются встроенным тест-раннером Node.js. После отправки изменений в `main` Vercel автоматически обновит Production, если репозиторий подключён к проекту.

Основные места для доработки:

- `api/index.js` — логика вебхука и вызов Gemini.
- `api/index.js`, `SYSTEM_PROMPT` — роль, стиль, язык и ограничения ответов ассистента.
- `api/index.js`, `isSearchIntent` и `searchWeb` — распознавание вопросов, для которых нужен поиск.
- `api/index.js`, функции работы с памятью — выбор и хранение контекста в Upstash.
- `tests/api.test.js` — автоматические проверки поведения; добавляйте тесты к новым возможностям.
- `.env.example` — список переменных для локальной разработки. Здесь должны быть только названия и примеры, никогда не реальные секреты.

Вебхук Яндекса должен отвечать быстро: Яндекс ожидает ответ примерно за 4,5 секунды. Поэтому код ограничивает время поиска и генерации ответа. При добавлении внешних сервисов учитывайте это ограничение.

## Безопасность и данные

- Никогда не добавляйте API-ключи и Redis-токены в код, GitHub, README или сообщения. Храните их в Environment Variables Vercel.
- `.env` и другие локальные файлы с переменными исключены из Git через `.gitignore`; для примера оставлен `.env.example` без секретов.
- Разговоры, сохранённые в Upstash, содержат текст сообщений. Включайте память только если вам подходит хранение этих данных в выбранной базе. Любой пользователь может попросить навык удалить свою историю.
- Правила, лимиты и стоимость сторонних сервисов зависят от их аккаунтов и могут меняться — проверяйте их на сайтах Gemini, Serper, Upstash и Vercel.

## Если что-то не работает

1. Откройте URL вебхука в браузере и проверьте, что он заканчивается на `/api` и возвращает `"ok": true`.
2. В Vercel проверьте, что `GEMINI_API_KEY` добавлен к нужному окружению, не содержит лишних пробелов, а после изменения был выполнен **Redeploy**.
3. Если обычный вопрос работает, а поиск — нет, проверьте `SERPER_API_KEY`. Поиск необязателен.
4. Если память не сохраняется, проверьте обе переменные Upstash и что они относятся к одной базе. Без них навык использует краткую историю Яндекса.
5. В Vercel откройте **Deployments → последнее развёртывание → Functions / Logs**. Удалите ключи и персональные данные перед передачей логов кому-либо.
6. Если в тестере Яндекс Диалогов ответ есть, но голосом навык не запускается, проверьте доступность навыка для тестирования, активационное имя и аккаунт Яндекса на колонке.
